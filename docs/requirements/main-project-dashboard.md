# Main Project Dashboard

## Main navigation

The ERP landing page has three primary actions:

1. Create New Project
2. Active Projects
3. Archived Projects

## Project identity

- One project record represents one GDS Job Code.
- GDS Job Codes are sequential, starting from GDS150 onward.
- Example format: GDS150, GDS151, GDS152.
- A Job Code must be unique.
- Project Lead is either Achint or Ikjot.

## Project creation

- A project can be created after a GDS Job Code is assigned.
- The user completes a mandatory project-creation form.
- The form can be saved as Draft.
- Draft projects do not appear in Active Projects.
- A project enters Active Projects only after all mandatory fields are completed and submitted.

## Active Projects dashboard

One row represents one GDS Job Code.

The initial dashboard columns are:

- GDS Job Code
- Project Name
- Brand
- Project Type
- Project Lead
- Project Manager
- Store/Site Address
- Site POC
- Project Status

The table may show a shortened address for layout purposes while retaining the complete address in the project record.

Clicking a project opens its Project Workspace.

Detailed internal information is not required in the initial dashboard table.

Internal project details will be added progressively as the project advances.

## Project Workspace

- Clicking an Active Project opens a dedicated Project Workspace.
- The first prototype needs only a basic overview of the initial project information.
- Future internal sections will be specified separately.
- Do not define departmental, financial, document or closure tabs yet.

## Prototype boundary

The initial visual prototype includes:

- Landing page
- Create Project form
- Active Projects dashboard
- Archived Projects placeholder
- Basic Project Workspace

The prototype:

- Uses fictional mock data only.
- Has no database.
- Has no authentication.
- Has no Google Drive integration.
- Has no production deployment.
- Does not implement financial calculations.
- Does not invent future internal project sections.
